# USOPGRID API v1

The full, browsable documentation is the developer portal at `/developers`
(source: `src/site/Developers.tsx`). The machine-readable contract is served at
`GET /api/v1/openapi.json` (OpenAPI 3.1, generated by `src/convex/lib/openapi.ts`
from the same registries the API runs on). This file is the engineering summary.

## Base URL and auth

```
https://<deployment>.convex.site/api/v1        (or your custom domain)
Authorization: Bearer sk_sandbox_…  |  sk_live_…
```

The key decides organization **and** environment. Publishable keys cannot call the API.

## Endpoints

| Method | Path | Notes |
|---|---|---|
| POST | `/payments` | Create + process. Idempotency-Key supported. |
| GET | `/payments` | `limit` (1–100), `cursor`, `status`, `created_gte`, `created_lte` |
| GET | `/payments/:id` | Adds `routing`, `attempt_log`, `refunds`, `timeline`, `customer`, `metadata` |
| POST | `/payments/:id/refund` | `{ amount?, reason? }`; Idempotency-Key supported |
| POST | `/routing/simulate` | Dry-run router with live configuration |
| GET | `/providers` | Capability registry |
| POST | `/fx/quotes` | `{ from, to, amount }` → 5-minute quote |
| GET | `/balance` | Ledger balances |
| GET | `/settlements` | Settlement batches |
| POST/GET | `/payouts` | Payouts to verified beneficiaries |
| GET | `/customers` | Per-currency lifetime volume |
| GET | `/reference` | Public: currencies (with minor units), countries, methods, states |
| GET | `/health` | Public liveness |
| GET | `/openapi.json` | Public spec |
| GET/POST | `/checkout/:linkId` | Public payment-link checkout (link-scoped, org environment) |
| POST | `/webhooks/providers/:connectionKey` | Inbound provider events (signature verified) |

## Request conventions

- JSON bodies, snake_case (earlier camelCase fields still accepted: `amountMinor`, `paymentMethod`, `customerEmail`).
- Amounts are integers in the currency's ISO 4217 minor unit.
- `metadata`: ≤ 50 keys, keys ≤ 40 chars, scalar values ≤ 500 chars.
- `X-Request-Id` / `X-Correlation-Id` (8–128 safe chars) is echoed as `X-USOPGRID-Request-Id`.

## Response envelope

```json
{ "status": "success", "requestId": "req_…", "data": { … } }
{ "status": "error", "requestId": "req_…", "error": { "code": "…", "message": "…", "retryable": false, "doc_url": "…" } }
```
Headers: `USOPGRID-Version: 2026-10-01`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Retry-After` on 429/503.

## Idempotency

`Idempotency-Key` (≤ 255 chars) on POST. Fingerprint = client-supplied fields
only. Same key + same body → original response; different body → 422;
concurrent duplicate → 409 (retryable). Keys expire after 24 h; a failed
request releases its key.

## Webhooks (outbound)

Headers: `X-USOPGRID-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, "t.body")>`,
`X-USOPGRID-Event`, `X-USOPGRID-Event-Id`, `X-USOPGRID-Delivery-Attempt`.
Retries: 30 s, 2 min, 10 min, 30 min, 2 h, 6 h, then dead-letter (replayable).

Events: `payment.successful`, `payment.pending`, `payment.requires_action`,
`payment.declined`, `payment.failed`, `payment.expired`, `payment.refunded`,
`refund.pending`, `refund.failed`, `payment.reconciliation_exception`.

## Rate limits and metering

120 requests/minute/key (fixed window, atomic in a single mutation). Every
authenticated request is metered per key/day/route with 4xx/5xx counts
(`apiUsage`), visible in Analytics and Reports.

## SDK

`sdk/typescript/usopgrid.ts`: zero-dependency client with automatic
idempotency keys reused across retries, Retry-After-aware backoff, typed
errors and `verifyWebhook`. Tested in `src/tests/sdk.test.ts`.
